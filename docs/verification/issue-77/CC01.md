Part of #79 and #77. Metadata/security foundation, not completed image upload or public gallery delivery.

## Implementation

Migration `20261025220052_community_foundation.sql` adds community profiles, artworks, append-only moderation events, persistent rate-limit buckets, indexes, constraints and server-only mutation functions. Existing product/reader-artwork/premium schemas and data are not rewritten.

Raw tables and RPCs are denied to anon/authenticated roles, including those claiming an admin role in user metadata. The application's server derives identity from Auth `getUser()` or the signed local adapter session; database functions independently verify current Auth account state, participation and rules, unlock/product state, administrator role, and expected revision/state. A narrow private definer helper checks Auth state because service_role has no raw auth.users SELECT privilege. Its row SHARE lock conflicts with email-unverification/deletion updates. All other community mutations are invoker functions restricted to service_role.

The service-only raw-table architecture and safe anonymous application projections are documented explicitly in `docs/spec/community-data.md`. It avoids raw PostgREST bypass of environment kill switches. Public/owner/admin DTOs do not expose object paths or user Auth IDs. Public queries are bounded and hide non-approved, deleted, archived-product, suspended/revoked/stale-rules content.

Local community state is independent of the product snapshot and persists via locked atomic file replacement. Local rate limits persist; Supabase rate limits use atomic database upserts. Case-insensitive usernames, reserved names, idempotent joins, separate rate-limited renames, retry-safe metadata reservations and optimistic moderation/edits/deletion are implemented. Removed-description edits retain the removed state and private reason. Public reads and new metadata submission enforce their respective flags; private joining can be rehearsed with uploads ON/public OFF.
