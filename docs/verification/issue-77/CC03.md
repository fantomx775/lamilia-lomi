# CC-03 private artwork upload evidence

Part of #81 and #77. Implemented in the dedicated branch; this is a locally verified checkpoint, not a completed cloud release.

## Implementation

One multipart image per request, with a 4MiB file limit and 4MiB+64KiB total-body limit. Up to three independent client previews submit sequentially. Server checks actual session, verified current adult participation, current rules, published book and real unlock before Sharp; persistent attempt/submission limits constrain abuse. Magic bytes and decoded format must match JPG/PNG/WebP. Decode is bounded to40MP, animation is rejected, orientation is normalized and output resized to2048px WebP with metadata removed.

Private Supabase/R2/local storage reuses the existing collection-image backend with a strictly isolated `community/<authorUUID>/<idempotencyUUID>` namespace. Community R2 PUT is conditional; legacy curated behavior is preserved. The browser receives app byte URLs only. Every media request rechecks current visibility/ownership/admin authorization and returns private/no-store bytes. Community paths are excluded from Next's optimizer allowlist so a transformed cached image cannot outlive a takedown. Existing product/category/asset optimizer paths remain available.

Migration `20261025230955_community_uploads.sql` adds service-only RLS upload reservations and RPCs. Exclusive writer leases, payload fingerprints, durable stored-state resumption and atomic pending-artwork finalization protect retries and concurrency. Deterministic failure cleanup is token-fenced; ambiguous results are reread before compensation. Tombstones revoke media before physical cleanup. A protected daily maintenance endpoint retries queued work even if the owner never returns or features are paused; immediate cleanup is the normal fast path. See SCHEDULER.md. Account-deletion-safe queue ownership/retention is still #85 work.

My Creations now has a focused upload drawer, book selection from published unlocks, drag/drop and picker, independent optional descriptions/rules confirmation, previews, partial success and stable-key retry. It persists statuses, private reasons, previews, explicit description editing and confirmed deletion. Approved edits return to pending and cut off old public bytes; removed edits remain removed. Mobile cards use a compact thumbnail layout. The shared drawer preserves its default Polish admin label, supports an English public close label, and restores focus and body scrolling. A PDP Share your art link is shown only for eligible unlocked owners. Private local files are ignored by Git.
