# Coloring Club data and repository boundary

The #79 migration is additive. Raw `community_profiles`, `community_artworks`, moderation events, and rate-limit buckets have RLS enabled and table privileges revoked from `PUBLIC`, `anon`, and `authenticated`. Direct PostgREST access intentionally returns permission denied, including for owner/admin reads. Anonymous gallery reads use server-only repository methods that check `COLORING_CLUB_PUBLIC_ENABLED`, select approved work for published products and active profiles, and return explicit allow-listed DTOs. This is the chosen interpretation of anonymous SELECT: public application projection, not `SELECT *` on raw storage metadata.

All mutations are SECURITY INVOKER RPCs callable only by `service_role`; the server resolves identity through a verified Supabase `getUser()` session (or signed local demo session). RPCs receive that actor UUID and recheck Auth confirmation, current `profiles.role` for moderation, community opt-in/adult/rules/suspension state, product publication/unlock, and revision/status preconditions in the database. `service_role` cannot select `auth.users`; a private, fixed-search-path SECURITY DEFINER helper returns only a verified/not-deleted boolean and takes a row-share lock so account verification/deletion cannot race the mutation. It is executable by `service_role` only. No request body can choose an actor or moderation state.

`LAMILIA_BACKEND=local` stores community fixtures in the separate git-ignored `data/lamilialomi-community.local.json`, using atomic temporary-file replacement and an exclusive lock directory for concurrent writers. Local actor UUIDs are deterministic hashes of the signed demo-session email and never appear in public DTOs. Local rate limits persist with the same snapshot; Supabase uses atomic database buckets keyed by SHA-256 only. `product_reader_artworks` and the shared product content snapshot are not modified.

This foundation reserves metadata only; #81 owns image-byte validation, storage writes and orphan cleanup. Physical account/artwork media cleanup, report retention, and final audit-retention policy are deferred to #85. The migration is not applied to Production by this work; apply only after normal release review and target checks.
