# Coloring Club data and repository boundary

The #79 migration is additive. Raw `community_profiles`, `community_artworks`, moderation events, and rate-limit buckets have RLS enabled and table privileges revoked from `PUBLIC`, `anon`, and `authenticated`. Direct PostgREST access intentionally returns permission denied, including for owner/admin reads. Anonymous gallery reads use server-only repository methods that check `COLORING_CLUB_PUBLIC_ENABLED`, select approved work for published products and active profiles, and return explicit allow-listed DTOs. This is the chosen interpretation of anonymous SELECT: public application projection, not `SELECT *` on raw storage metadata.

All mutations are SECURITY INVOKER RPCs callable only by `service_role`; the server resolves identity through a verified Supabase `getUser()` session (or signed local demo session). RPCs receive that actor UUID and recheck Auth confirmation, current `profiles.role` for moderation, community opt-in/adult/rules/suspension state, product publication/unlock, and revision/status preconditions in the database. `service_role` cannot select `auth.users`; a private, fixed-search-path SECURITY DEFINER helper returns only a verified/not-deleted boolean and takes a row-share lock so account verification/deletion cannot race the mutation. It is executable by `service_role` only. No request body can choose an actor or moderation state.

`LAMILIA_BACKEND=local` stores community fixtures in the separate git-ignored `data/lamilialomi-community.local.json`, using atomic temporary-file replacement and an exclusive lock directory for concurrent writers. Local actor UUIDs are deterministic hashes of the signed demo-session email and never appear in public DTOs. Local rate limits persist with the same snapshot; Supabase uses atomic database buckets keyed by SHA-256 only. `product_reader_artworks` and the shared product content snapshot are not modified.

The #81 upload extension adds private upload reservations and an opaque `community/<author UUID>/<idempotency UUID>` object key. The server checks membership, current published-book status, and unlock before bounded image decode; it validates signature and decoded format, caps input at 4 MiB/40 MP, rotates/resizes, strips metadata, and stores WebP. Reservation ownership is exclusive while bytes are being written. A durable `stored` state lets an identical retry finalize after an ambiguous database response without overwriting or re-uploading the object. Artwork metadata becomes pending atomically only after storage is confirmed. Deterministic authorization/validation failures schedule cleanup; transient failures remain retryable, and the protected scheduled cleanup drains durable cleanup records.

All community image bytes, including approved images, are streamed through the status-gated application media route with `private, no-store` on every response. Community paths are excluded from the Next image optimizer allowlist. Provider signed URLs are never sent to the browser; no CDN cache or cache purge is part of the access control. Physical account deletion/media cleanup, report retention, and final audit-retention policy are deferred to #85. The migration is not applied to Production by this work; apply only after normal release review and target checks.

The #84 `community_artwork_likes` table is service-role-only under RLS; each `(artwork_id,user_id)` pair is unique. The `community_set_artwork_like` invoker RPC rechecks confirmed Auth, active adult membership/current rules, approved/published artwork, current creator eligibility and published product. Hearts do not require book unlock. Insert/delete triggers update `likes_count` atomically without changing artwork revision or `updated_at`. Suspension or withdrawal removes a member's reactions and decrements counts in the same transaction; account deletion cascades. Public reads batch-check only the current viewer's IDs for the bounded page and never return liker identities. Popular pages are all-time and use a stable sort tuple, although live count changes can move an artwork across cursor pages; the UI deduplicates returned artwork IDs.
